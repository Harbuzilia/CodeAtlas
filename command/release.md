# Release Command | Команда /release

## Назначение
Автоматизировать выпуск новых версий проекта: анализ Conventional Commits с прошлого тега, бамп версии в `package.json` **и** `registry.json`, формирование новой секции в `CHANGELOG.md` и создание аннотированного Git-тега.

## Вход
- `/release <patch|minor|major>` (например, `/release minor`)
- `/release` без аргументов — по умолчанию bump `patch`
- Реализация: `scripts/release-gen.mjs` (`npm run release -- <тип> [флаги]`)

## Флаги
- `--dry-run` — полный прогон гейтов + превью секции changelog, **ни один tracked-файл не меняется** (можно на грязном дереве — будет предупреждение)
- `--no-tag` — коммит релиза создаётся, тег нет
- `--no-verify` — релизный коммит без pre-commit хука (если все гейты уже пройдены вручную)

## Автоматический конвейер (Pipeline)
1. **Проверка чистоты дерева**: `git status` чист (для dry-run — предупреждение).
2. **Quality Gates**: скрипт сам прогоняет `npm run validate:all`, `npm run scan:secrets`, `npm run eval:routes`. Любой красный гейт = отказ релиза.
3. **Анализ коммитов**: сбор коммитов с последнего тега (если тегов нет — с начала истории) и группировка:
   - `feat!` / `BREAKING CHANGE` → 💥 Breaking Changes
   - `feat` → 🚀 Новые возможности
   - `fix` → 🐛 Исправления
   - `perf` → ⚡ Производительность
   - `docs` → 📚 Документация
   - прочее (`refactor`/`test`/`chore`/`build`/`ci`/`style`/без типа) → 🔧 Прочее
4. **Подсказка типа бампа**: если история коммитов противоречит выбранному типу (есть `feat` при `patch` и т.п.) — предупреждение (не блокирует).
5. **Бамп версии**: `package.json` и `registry.json` (формулировка registry меняется хирургически, без переформатирования файла).
6. **Обновление CHANGELOG.md**: секция `## [дата] — Release vX.Y.Z` вставляется после разделителя под шапкой.
7. **Git Commit & Tag**: коммит `chore(release): vX.Y.Z` и аннотированный тег `vX.Y.Z`.

## Пример вывода
```
## 🏷️ Релиз v1.1.0 успешно подготовлен!

- **Тип бампа**: minor
- **Новая версия**: 1.1.0 (package.json + registry.json)
- **Тег создан**: `v1.1.0`
- **CHANGELOG.md**: секция из 9 коммитов (validate:all / scan:secrets / eval:routes пройдены)

Чтобы запушить релиз с тегами:
```bash
git push && git push --tags
```
```

# Plan Command | Команда /plan

## Назначение
Декомпозировать сложную фичу или рефакторинг на атомарные задачи (INVEST) и сохранить чек-лист в `.opencode/task_state.md` для пошагового исполнения агентами.

## Вход
- `/plan <описание фичи/задачи>`
- `/plan` без аргументов — уточняющий диалог с генерацией архитектурного плана

## Автоматический режим
1. Исследовать кодовую базу через `contextscout` или `repomap` / `ast-index`.
2. Загрузить агента `planner`.
3. Разбить задачу на независимые, проверяемые шаги:
   - S/M/L сайзинг
   - Выявление зависимостей и блокеров
   - Определение целевых файлов и исполнителей (`coder`, `tester`, `docwriter`)
4. Записать структурированный чек-лист в `.opencode/task_state.md`.
5. Вывести план пользователю.

## Выход (формат)
```
## 📋 План реализации: [Название задачи]

### Чек-лист задач (.opencode/task_state.md):
- [ ] 1. [Coder] Создать DTO и сущности базы данных (`src/models/user.dto.ts`)
- [ ] 2. [Coder] Реализовать бизнес-логику регистрации (`src/services/user.service.ts`)
- [ ] 3. [Tester] Написать unit-тесты на валидацию и дубликаты (`tests/user.service.spec.ts`)
- [ ] 4. [DocWriter] Обновить спецификацию API и README (`docs/api.md`)

### Риски и зависимости:
- Риск: ... | Смягчение: ...
```

## Пример
```
/plan Реализовать аутентификацию через Google OAuth2
```

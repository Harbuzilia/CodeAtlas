# Conflict Command | Команда /conflict

## Назначение
Найти файлы с незавершенными Git-конфликтами (`<<<<<<<`, `=======`, `>>>>>>>`), выполнить семантическое слияние обеих веток без потери кода и проверить работоспособность проекта.

## Вход
- `/conflict <файл>` (например, `/conflict src/services/user.ts`)
- `/conflict` без аргументов — сканирование всех файлов репозитория на наличие конфликтов

## Автоматический режим
1. Загрузить навык `git-conflict-resolution`.
2. Найти неразрешенные маркеры конфликта.
3. Проанализировать семантику изменений с обеих сторон (`HEAD` и входящая ветка).
4. Объединить логику, сохранив типы, параметры и обработку ошибок.
5. Прогнать `npm run validate:all` и тесты.

## Пример вывода
```markdown
## 🔀 Конфликт в `src/services/user.ts` успешно разрешен!

### Примененное решение:
- Сохранен новый параметр `includeRoles` из feature-ветки
- Сохранена обработка ошибок из `main`
- Маркеры конфликта удалены

Все Quality Gates и тесты пройдены: ✅ OK
```

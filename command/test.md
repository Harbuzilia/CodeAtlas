# Test Command | Команда /test

## Назначение
Быстро сформировать комплексный тест-план и сгенерировать недостающие тесты (positive, negative, edge cases) по паттерну Arrange-Act-Assert.

## Вход
- `/test <файл/модуль/фича>`
- `/test --smart` — молниеносный запуск только затронутых тестов (Test Impact Analysis) за миллисекунды
- `/test` без аргументов — тестирование недавно измененных файлов по `git diff`

## Автоматический режим
1. Определить стек и тестовый фреймворк проекта (jest, vitest, pytest, xUnit, playwright).
2. Загрузить профильный language skill (`typescript`, `python`, `csharp`) и при необходимости `e2e-playwright`.
3. Делегировать генерацию/доработку тестов агенту `tester` (или `uitester` для визуальных сценариев).
4. Проверить обязательные требования к тестам:
   - Минимум 1 positive test (happy path)
   - Минимум 1 negative test (обработка ошибок)
   - Edge cases (граничные значения, null, пустые массивы)
   - Моки для внешних API, БД и сети
5. Выполнить запуск тестов и предоставить отчет о результатах.

## Выход (формат)
```
## 🧪 Результаты тестирования

### Созданные/обновленные файлы тестов:
- `tests/unit/auth.service.spec.ts`

### Покрытие сценариев:
- [x] Positive: Успешная аутентификация по валидному JWT
- [x] Negative: Истекший токен (401 Unauthorized)
- [x] Edge case: Пустой заголовок Authorization

### Результаты прогона:
- Запущено: N
- Успешно: N
- Ошибок: 0
```

## Пример
```
/test
/test src/controllers/user.controller.ts
```

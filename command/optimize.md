# Optimize Command | Команда /optimize

## Назначение
Провести целевой аудит производительности указанного файла/модуля или всего проекта, найти узкие места и предложить конкретные оптимизации с замерами.

## Вход
- `/optimize <путь/модуль>`
- `/optimize` без аргументов — анализ недавно измененных файлов по `git diff`

## Автоматический режим
1. Загрузить навык `performance-optimization` (`skills/performance-optimization/SKILL.md`).
2. Использовать `ast-index` / `repomap` для анализа иерархии вызовов и структуры данных.
3. Проверить ключевые зоны риска:
   - Базы данных / ORM: N+1 запросы, отсутствие `.AsNoTracking()`, отсутствие индексов.
   - I/O: синхронные блокирующие вызовы, отсутствие потоковой передачи (Streams/Generators).
   - Алгоритмы: вложенные циклы \(O(n^2)\), избыточные аллокации памяти в hot paths.
   - Frontend: лишние ре-рендеры, тяжелые неиспользуемые импорты (tree-shaking).
4. Сформировать структурированный отчет с готовыми diff-решениями.

## Выход (формат)
```
## ⚡ Отчет по производительности: [Модуль]

### Критичные узкие места:
1. `path/to/file.ts:42` — N+1 запрос к БД
   - Проблема: ...
   - Fix: ...

### Предлагаемый Diff:
```diff
- problematic_code()
+ optimized_code()
```

### Рекомендации по бенчмаркам:
- Команда для замера: `...`
```

## Пример
```
/optimize src/services/OrderService.cs
```

# Writing Plans Skill

> План — это файл, по которому исполнитель (человек или субагент) работает без домыслов.
> Адаптировано из ядра obra/superpowers (MIT).

## Зачем

«Улучшить авторизацию» — не план, а пожелание. Исполнитель потратит шаги на интерпретацию. План из bite-size шагов с точными файлами и проверками превращает задачу в конвейер и выживает компакцию контекста (файл перечитывается, чат — нет).

## Структура шага (обязательные поля)

```markdown
## Шаг N: <действие — глагол + объект>
- Файлы: `src/auth/session.ts` (+ `src/auth/__tests__/session.test.ts`)
- Действия: что именно изменить (добавить/удалить/переписать — конкретика)
- Проверка: `npm test -- session` — 12/12 зелёные (это критерий ГОТОВНОСТИ шага)
- Зависимости: после Шага M (если есть)
```

## Правила

1. **Шаг = 2-5 минут работы** одного исполнителя. Больше — разбей. Меньше — склей.
2. **Файлы по точным путям.** Не «в модуле авторизации», а `src/auth/session.ts:42`.
3. **Каждый шаг проверяем командой.** Нет команды проверки — шаг не готов к плану (сначала придумай, как узнаешь, что сделано).
4. **Порядок обоснован**: зависимости раньше потребителей; рискованные шаги — раньше (чтобы падение было дешёвым).
5. **Не проектировай в плане реализацию целиком** — только контракт шага: вход, выход, проверка. Исполнитель сам решает, как.
6. **Границы scope явно:** что НЕ входит в задачу (иначе исполнителя понесёт).
7. **Пиши план в файл** (`.opencode/task_plan.md` / проектный план), не в чат. Чекбоксы обновляются по ходу (`- [x]`).

## Плохо / хорошо

| Плохо | Хорошо |
|-------|--------|
| «Разобраться с ошибкой логина» | «Шаг 1: воспроизвести — запустить `npm test -- login`, зафиксировать текст падения» |
| «Обновить доки» | «Шаг 3: README §2 — синхронизировать список команд с `package.json` (проверка: docs-sync гейт зелёный)» |
| «Оптимизировать запросы» | «Шаг 2: заменить N+1 в `getUserOrders` на один JOIN; проверка: в логе 1 запрос вместо 41» |

## Чеклист плана

- [ ] Каждый шаг 2-5 минут, один исполнитель
- [ ] Точные файлы и команды проверки
- [ ] Порядок шагов обоснован зависимостями
- [ ] Scope-границы «не входит» названы
- [ ] План в файле, шаги с чекбоксами

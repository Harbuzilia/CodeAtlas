# OpenAPI 3.1 Spec-First Skill

Contract-First: спецификация (OpenAPI YAML/JSON или автоген из Pydantic/Zod/ASP.NET) — единый источник истины между frontend и backend.

## Принципы

1. **Строгая валидация**: все входные тела, query-параметры, заголовки — типы, ограничения длины, regex, defaults.
2. **Breaking changes запрещены**: нельзя удалять/переименовывать поля ответов, делать опциональные поля запроса обязательными. Можно: добавлять опциональные поля, новые эндпоинты.
3. **Версионирование путей**: `/api/v1/...`.
4. **Стандартные коды**: 200, 201, 204, 400, 401, 403, 404, 409, 422, 500.
5. **Единый формат ошибок**: `ErrorResponse { code, message, details[] }` или RFC 7807 Problem Details.

## Требования к схемам

- `operationId` на каждой операции (для генерации клиентов).
- DTO с валидацией: `format: email|uuid|date-time`, `minLength/maxLength`, `required` явно.
- Переиспользование через `$ref: '#/components/schemas/...'`.

## Чек-лист проверки API

- [ ] Пути с префиксом версии
- [ ] Стандартные HTTP-коды
- [ ] Валидационные ограничения на всех DTO
- [ ] Стандартизированный формат ошибок
- [ ] Отсутствие breaking changes для существующих клиентов

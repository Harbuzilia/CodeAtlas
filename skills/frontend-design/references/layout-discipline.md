# Layout Discipline — полные правила (веб)

Дочитывать при: сложных hero, bento-секциях, длинных списках, спека-таблицах, цитатах, сомнениях по плотности контента.

## Hero (hard rules)
- Помещается в первый viewport (`min-h-[100dvh]`, fallback `100svh`), CTA и главный визуал видны без скролла.
- Максимум 4 текстовых элемента: заголовок, подзаголовок, CTA, соц-доказательство. «Истории» и длинные описания — ниже.
- Нет статичной центрированной hero-композиции при VARIANCE ≥ 5: asymmetry, grid-break, mask, scroll-triggered motion.
- Нет лого-стены внутри hero; она живёт отдельной секцией ниже fold. Мини-строка соц-доказательства ≤ 4–5 лого допустима внутри hero.
- CTA: одна строка, ≤ 4 слова. Макс. 2 primary-действия на всю страницу. Градиентные CTA запрещены.
- Текст поверх изображения/видео: overlay/gradient `bg-gradient-to-t from-black/60 to-transparent`, контраст текста ≥ 4.5:1.

## Eyebrow-математика (обязательная проверка)
1. Посчитать видимые секции (исключая nav и footer).
2. Посчитать small caps / eyebrow-строки.
3. Норма: ≤ ceil(секции / 3). Лишние удалить или понизить до body-текста.
Разрешены только когда несут реальную категорию (тип секции, номер шага, статус). Не как «красивая короткая строка».

## Диверсификация layout
- Никаких двух подряд секций из одного layout-семейства (centered → 2-col-image-right → 2-col-image-left — это ОДНО семейство «центрировано + 2-колонки», запрещено).
- Ротация: centered → split (media right) → full-bleed quote → zigzag → carousel. Максимум 2 zigzag подряд, 3-й меняет ось или масштаб.
- Каждая секция заявляет layout-семейство до генерации.

## Bento / карточки
- 3 одинаковые карточки в ряд запрещены. Альтернативы: asymmetric grid, 2-col zigzag, scroll-snap, list + side-visual.
- В multi-cell сетке минимум 2–3 ячейки с реальной визуальной вариацией: изображение, brand-градиент (не AI-purple), паттерн, тонированный фон. Крем-на-креме только с типографикой внутри — скучный AI-дефолт.
- Число ячеек = числу реальных блоков контента. Нет filler-карточек «для симметрии».
- Градиентные бордеры карточек запрещены. Внутри карточки нет мини-hero.
- Mobile-collapse прописан явно для каждой multi-column секции (`w-full px-4` на `<768px`).

## Split-header
- Только когда реально 2 содержательных столбца (headline+CTA слева, поддерживающий визуал/специфика справа), оба ≥ 40% композиции.
- Запрещён как пассивный filler (текст слева, пустота справа).
- Не более 1 split-header на страницу; не рядом с full-bleed center-hero без контрастной секции между ними.

## Отступы и стабильность
- Section padding из spacing-scale проекта, не ad-hoc значениями. Межсекционные отступы больше внутриблочных.
- Hero на full-width теме: не перекрывает nav.
- `<details>`/accordion как faq-структура, не как единственный дизайн-ход.
- Mobile: `min-h-[100dvh]` (НЕ `h-screen`), явный collapse для high-variance layout.

## Плотность контента
- Форма секции по умолчанию: заголовок ≤ 8 слов + подпараграф ≤ 25 слов + один визуал ИЛИ один CTA. Больше — только по задаче секции.
- Нет data-dump секций: 20-строчная таблица публикаций, 30 наград, гигантская pricing-матрица на маркетинговой странице — неверный layout. Вместо: top 3–5 + ссылка «весь список», marquee/carousel для breadth, отдельная страница если данные — продукт.
- Список > 5 пунктов — не длиннее `<ul>`, а другой компонент: 2-col split с группами, карточки с изображением, tabs/accordion, горизонтальный scroll-snap pills, carousel, marquee.
- **Спека-таблицы (паттерн Marrow):** длинная таблица с `border-b` на каждой строке — бан. Альтернативы: 2-col карточки (название + крупное значение + «зачем это» в одну строку); scroll-snap pills; группировка 10 спек в 3 кластера с одним разделителем на кластер; featured-vs-rest (3–4 hero-спеки плитками, остальное под disclosure «все характеристики»).

## Фейковые числа
- `92%`, `4.1×`, `48k`, `5.8 mm` — только из реальных данных (бриф, гайдлайны, публичные метрики) или с явной пометкой mock. Выдуманная «инженерная точность» — бан.

## Цитаты и отзывы
- Максимум 3 строки текста цитаты. Длиннее — резать. Это сниппет, не полный отзыв.
- Атрибуция: имя + роль (+ компания опционально). Никогда только имя («— Sarah»).
- Кавычки: типографские « » или вообще без. Не ASCII-прямые `"`.
- Нет em-dash внутри цитаты как дизайн-приём.

## Copy self-audit (перед ship)
Перечитать КАЖДУЮ видимую строку страницы (заголовки, подзаголовки, eyebrow, кнопки, body, captions, alt, footer, ошибки). Флаговать:
- грамматически сломанные;
- с неясными референтами («мы планируем так и оставаться» без контекста);
- звучащие как AI-галлюцинация (милый, но неверный вордплей, натянутые метафоры, «элегантное ничто»);
- читающиеся как «LLM старается звучать умно» (пассивно-агрессивная скромность, fake-craftsman ярлыки, мнимо-поэтичная микро-мета).
Каждую флагнутую — переписать. Сомневаешься — заменить на простую функциональную фразу. Милая AI-копия хуже скучной.
- Один регистр копии на страницу: не мешать технический mono («47 задач · 0.6 ctx-switches/day»), редакционную прозу и маркетинговый панч в одной композиции.

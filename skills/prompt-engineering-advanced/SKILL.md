# Advanced Prompt Engineering Skill

<context>
Этот скилл содержит стандарты и техники создания высокоплотных, надежных и защищенных от галлюцинаций промптов для LLM и автономных агентов.
Используется оркестратором `openagent` (для фонового улучшения задач), агентами `planner`, `docwriter` и командой `/prompt`.
</context>

## 1. Архитектура идеального системного промпта (XML-Tagging)

Используй четкие семантические XML-теги для разделения контекста, инструкций и ограничений:

```xml
<system_prompt>
  <role>
    Ты — Senior AI Engineer...
  </role>

  <context>
    Вводные данные проекта, стек, архитектурные ограничения.
  </context>

  <instructions>
    1. Проанализируй входные данные...
    2. Построй пошаговый план...
    3. Сгенерируй код с тестами...
  </instructions>

  <constraints>
    - [NEGATIVE] Никогда не используй устаревшие API...
    - [PRECISION] Не делай догадок — проверяй факты по кодовой базе...
    - [OUTPUT] Выводи результат строго в указанном формате...
  </constraints>

  <output_format>
    ```json
    { "status": "success", "result": "..." }
    ```
  </output_format>
</system_prompt>
```

## 2. Ключевые техники надежности

1. **Ambient Intent Expansion**: Превращение краткого запроса пользователя (*"сделай форму входа"*) в полную спецификацию (UI + Validation + API + Error Handling + Tests).
2. **Few-Shot Demonstration**: Включение 1-2 эталонных примеров пар `Вход → Выход` для устранения неоднозначности.
3. **Chain-of-Thought (CoT) & Reasoning Tokens**: Требование структурировать ход мыслей перед выдачей финального ответа.
4. **Guardrails & Negative Constraints**: Явный запрет частых антипаттернов (например: *«Не используй inline стили»*, *«Не удаляй существующие комментарии»*).

---

## 3. Чек-лист качества промпта

- [ ] Четко разделены Роль, Контекст, Инструкции и Ограничения
- [ ] Описан точный формат желаемого вывода (JSON/Markdown/Diff)
- [ ] Добавлены Negative Constraints (что делать категорически запрещено)
- [ ] Устранены двусмысленные формулировки

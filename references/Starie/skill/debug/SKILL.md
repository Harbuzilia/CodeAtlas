# Debug Skill

## Процесс отладки

### 1. Воспроизведение
- Получить точные шаги воспроизведения
- Определить ожидаемое vs фактическое поведение
- Изолировать проблему (какой компонент?)

### 2. Сбор информации
- Логи и stack trace
- Входные данные
- Состояние системы
- Недавние изменения в коде

### 3. Гипотезы
- Сформулировать 2-3 возможные причины
- Начать с самой вероятной
- Проверить каждую систематически

### 4. Исправление
- Минимальное изменение для fix
- Добавить тест на этот случай
- Проверить что не сломалось другое

## Типичные причины багов

### Null/Undefined
```
Симптом: NullReferenceException, undefined is not a function
Проверить: все ли данные инициализированы?
```

### Race Condition
```
Симптом: баг воспроизводится не всегда
Проверить: есть ли параллельный доступ к данным?
```

### Off-by-one
```
Симптом: пропущен первый/последний элемент
Проверить: границы циклов и индексов
```

### State Mutation
```
Симптом: данные неожиданно изменились
Проверить: кто ещё имеет доступ к объекту?
```

## Формат вывода

```
## Проблема
[описание бага]

## Анализ
[что проверил, что нашёл]

## Причина
[root cause]

## Исправление
[код fix + объяснение]

## Тест
[тест чтобы баг не вернулся]
```

## Инструменты
- Логирование в ключевых точках
- Breakpoints и step-through
- Unit тест воспроизводящий баг
- Git bisect для поиска коммита

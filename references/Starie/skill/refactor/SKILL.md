# Refactor Skill

## Принципы безопасного рефакторинга

### Перед началом
1. Убедиться что есть тесты (или написать)
2. Понять текущее поведение
3. Делать маленькие шаги
4. Проверять после каждого шага

### Паттерны рефакторинга

#### Extract Method
Когда: длинный метод, повторяющийся код
```
До:  один метод на 100 строк
После: несколько методов по 10-20 строк
```

#### Extract Class
Когда: класс делает слишком много
```
До:  UserService с 20 методами
После: UserService + UserValidator + UserNotifier
```

#### Replace Conditional with Polymorphism
Когда: много if/switch по типу
```
До:  if (type == "A") ... else if (type == "B") ...
После: interface IHandler + конкретные реализации
```

#### Introduce Parameter Object
Когда: метод принимает много параметров
```
До:  CreateUser(name, email, phone, address, ...)
После: CreateUser(UserCreateRequest request)
```

## Чеклист

- [ ] Тесты проходят до рефакторинга
- [ ] Изменения минимальны и атомарны
- [ ] Тесты проходят после каждого шага
- [ ] Публичный API не изменился (если не планировалось)
- [ ] Нет регрессий в функциональности

## Формат вывода

```
## Анализ
[что не так с текущим кодом]

## План рефакторинга
1. [шаг 1]
2. [шаг 2]
...

## Результат
[улучшенный код с объяснением]
```

## Не делать
- ❌ Рефакторинг и новая функциональность одновременно
- ❌ Большие изменения без тестов
- ❌ Изменение поведения под видом рефакторинга

## Алгоритм работы

### Шаг 1: Анализ запроса

```prompt
Проанализируй запрос: $ARGUMENTS

Определи:
- Тип задачи (feature/bugfix/refactor/deploy/test/other)
- Сложность (simple/medium/complex)
- Какие файлы/модули затронуты
- Какие шаги нужны
```

### Шаг 2: Поиск готового workflow

```bash
# Проверяем есть ли готовый workflow
ls .agent/workflows/
```

**Проверь соответствие:**
| Тип задачи | Готовый workflow |
|------------|-----------------|
| feature | `/feature` |
| bugfix | `/bugfix` |
| refactor | `/refactor` |
| review | `/review` |
| tasks | `/tasks` |

### Шаг 3: Решение

**Если есть подходящий workflow:**
```prompt
Найден готовый workflow: /[name]
Использую его для выполнения задачи.
```
→ Делегируй выполнение готовому workflow

**Если нет подходящего:**
→ Переходи к генерации нового workflow

## Генерация нового workflow

### Шаг 4: Создание плана

```prompt
Создай пошаговый план выполнения:

## Workflow: [название]

### Шаги:
1. [Описание шага 1]
2. [Описание шага 2]
...

### Условия успеха:
- [ ] Критерий 1
- [ ] Критерий 2

ПОКАЖИ план пользователю и ЖАДИ подтверждения.
```

### Шаг 5: Выполнение (после одобрения)

```prompt
Выполняй шаги по одному.
После каждого шага — проверяй результат.
При ошибке — остановись и сообщи пользователю.
```

### Шаг 6: Сохранение workflow

**После успешного выполнения:**

```prompt
✅ Задача выполнена успешно!

Хочешь сохранить этот workflow для повторного использования?

Предлагаемое имя: /[suggested-name]

Ответь "да" или предложи другое имя.
```

**Если пользователь согласен:**

Создай файл `.agent/workflows/[name].md`:

```markdown
---
description: [Описание workflow]
icon: [подходящий emoji]
---

# [Название] Workflow

[Описание что делает]

## Шаги

### 1. [Название шага]
```prompt или bash
[содержимое]
```

### 2. [Название шага]
...

## Как использовать
```
/[name] описание задачи
```
```

## Примеры использования

```
/wf-smart настрой CI/CD для проекта
→ Нет готового workflow
→ Генерирую план: 1. Создать .github/workflows, 2. Настроить jobs...
→ Выполняю
→ Предлагаю сохранить как /ci-cd

/wf-smart добавь новую фичу авторизации
→ Есть готовый /feature
→ Использую его
```

## Правила генерации workflows

### Формат шагов
- Используй `prompt` для инструкций AI
- Используй `bash` для команд терминала
- Добавляй `// turbo` для безопасных авто-команд

### Обязательные элементы
- Frontmatter с description и icon
- Чёткие шаги с номерами
- Условия выхода (успех/провал)
- Примеры использования

### Именование
- Короткие, понятные имена
- kebab-case: `deploy-staging`, `db-migrate`
- Не конфликтуют с существующими

## Защита от ошибок

<critical_rules>
  <rule id="approval_gate">
    ВСЕГДА показывай план перед выполнением.

  </rule>
  
  <rule id="step_by_step">
    Выполняй по одному шагу.
    Проверяй результат каждого.
  </rule>
  
  <rule id="stop_on_error">
    При ошибке — СТОП.
    Сообщи пользователю, не пытайся автоисправить.
  </rule>
  
  <rule id="save_on_success">
    После успеха — предлагай сохранить.
    Но не навязывай, это опционально.
  </rule>
</critical_rules>

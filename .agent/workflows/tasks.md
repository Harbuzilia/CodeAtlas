# Task Processor Workflow

Автоматическая обработка задач из файла плана.

## Конфигурация

```yaml
source: PLAN.md               # Откуда брать задачи
task_pattern: "- [ ]"         # Паттерн незавершённой задачи
done_pattern: "- [x]"         # Паттерн завершённой задачи
max_tasks_per_run: 5          # Максимум задач за запуск
```

## Шаги

### 1. Загрузить план
// turbo
```bash
cat PLAN.md
```

### 2. Найти следующую задачу
```prompt
Найди первую строку с `- [ ]` в PLAN.md

Если нет незавершённых задач → сообщи "Все задачи выполнены!"
Если есть → извлеки текст задачи
```

### 3. Валидация задачи
```prompt
Проверь задачу:
- Достаточно ли информации для выполнения?
- Это атомарная задача (можно сделать за 1 сессию)?
- Не заблокирована ли другими задачами?

Если проблемы → пропусти, отметь как `- [?]` (need clarification)
```

### 4. Анализ типа задачи
```prompt
Определи тип:
- `code` → новый код или изменение
- `test` → написание тестов
- `docs` → документация
- `fix` → исправление бага
- `refactor` → рефакторинг

Выбери подходящий workflow или агента.
```

### 5. Выполнение (условный роутинг)

Если type == 'code':
```prompt
Выполни задачу как core/opencoder.
Следуй контексту из context/core/standards/code.md
```

Если type == 'test':
```prompt
Выполни как tester.
Следуй контексту из context/core/standards/tests.md
```

Если type == 'fix':
```prompt
Выполни workflow /bugfix с описанием задачи
```

Если type == 'refactor':
```prompt
Выполни workflow /refactor с описанием задачи
```

### 6. Верификация
```bash
# Запуск тестов
npm test || dotnet test || pytest || echo "No tests configured"
```

### 7. Условие: успех?

Если тесты прошли:
```prompt
Отметь задачу как выполненную в PLAN.md:
Замени `- [ ] задача` на `- [x] задача`
```

Если тесты упали:
```prompt
Задача не выполнена. Отметь как `- [!] задача (failed)`
Продолжи со следующей задачей.
```

### 8. Коммит
// turbo
```bash
git add .
git commit -m "✅ complete: [описание задачи]"
```

### 9. Проверка лимита

```prompt
Проверь сколько задач уже выполнено в этом запуске.
Если < 5 → вернись к шагу 2
Если >= 5 → остановись, выведи summary
```

### 10. Итоговый отчёт
```prompt
# Task Processor Summary

## Выполнено в этом запуске
- [x] Задача 1
- [x] Задача 2
...

## Осталось
- [ ] Задача N
...

## Проблемы
- [!] Задача с ошибкой
- [?] Задача требует уточнения
```

---

## Формат PLAN.md

```markdown
# План проекта

## Sprint 1
- [ ] Создать модель User
- [ ] Добавить API /users
- [ ] Написать тесты для User API

## Sprint 2
- [ ] ...
```

## Как использовать

```
/tasks              # Обработать следующие задачи из PLAN.md
/tasks 3            # Обработать ровно 3 задачи
/tasks --dry-run    # Показать что будет сделано без выполнения
```

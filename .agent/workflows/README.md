# Workflows — Руководство по созданию

Это руководство поможет создавать свои workflows.

---

## Структура workflow файла

```yaml
---
description: Краткое описание (показывается в списке)
icon: workflow          # Текстовая метка для различия
---

# Название Workflow

Подробное описание что делает workflow.

## Шаги

### 1. Название шага
```prompt
Инструкции для агента
```

### 2. Следующий шаг
```bash
# Команды терминала
```
```

---

## Типы блоков

### `prompt` — инструкции для ассистента
```prompt
Сделай X используя Y.
Учти Z.
```

### `bash` — команды терминала
```bash
npm test
git add .
```

### Условия (текстом)
```markdown
Если условие:
```prompt
Сделай это
```

Иначе:
```prompt
Сделай другое
```
```

### Циклы (текстом)
```markdown
Повторять пока [условие]:

#### Шаг в цикле
```prompt
...
```
```

---

## Специальные аннотации

### `// turbo` — авто-выполнение без подтверждения
```markdown
### Шаг
// turbo
```bash
ls -la
```
```

### `$ARGUMENTS` — подстановка аргументов пользователя
```markdown
/myworkflow аргументы здесь
             └── подставится в $ARGUMENTS
```

## Переменные и состояние

### Временные файлы
```bash
# Сохранить состояние
echo "data" > .tmp/my-state.md

# Прочитать
cat .tmp/my-state.md
```

### Стандартные пути
| Путь | Назначение |
|------|------------|
| `.tmp/` | Временные файлы workflow |
| `context/` | Стандарты и паттерны |
| `PLAN.md` | План задач |

## Готовые паттерны

### Паттерн: Анализ → План → Выполнение
```markdown
### 1. Анализ
```prompt
Проанализируй $ARGUMENTS
Сохрани в .tmp/analysis.md
```

### 2. План
```prompt
Создай план на основе анализа
Покажи пользователю
```

### 3. Выполнение (цикл)
```prompt
Выполняй пункты плана по одному
Отмечай выполненные
```
```

### Паттерн: Тест-first
```markdown
### 1. Написать тест
```prompt
Сначала напиши тест для $ARGUMENTS
Тест должен падать
```

### 2. Реализация
```prompt
Напиши код чтобы тест прошёл
```

### 3. Проверка
```bash
npm test
```
```

### Паттерн: Итеративное улучшение
```markdown
### Цикл улучшения

Повторять пока качество < целевого:

#### Оценка
```prompt
Оцени текущее состояние
```

#### Улучшение
```prompt
Улучши самый проблемный аспект
```

#### Тест
```bash
npm test
```
```

## Примеры использования

### Минимальный workflow
```yaml
---
description: Простой пример
---

# Hello Workflow

### 1. Приветствие
```prompt
Поздоровайся и скажи что будешь делать: $ARGUMENTS
```

### 2. Делаем
```prompt
Выполни $ARGUMENTS
```

### 3. Прощание
```prompt
Попрощайся и подведи итог
```
```

### Workflow с внешней интеграцией
```yaml
---
description: Обработка из Trello/Jira
---

### 1. Загрузить задачу
```bash
# Пример: забрать задачу из API
curl -s "https://api.trello.com/..." > .tmp/task.json
```

### 2. Распарсить
```prompt
Прочитай .tmp/task.json
Извлеки: title, description, labels
```

### 3. Выполнить
```prompt
Выполни задачу: [title]
Требования: [description]
```

### 4. Обновить статус
```bash
# Отметить как Done
curl -X PUT "https://api.trello.com/..." 
```
```

---

## Советы

1. Держи шаги атомарными — один шаг = одно действие
2. Используй .tmp/ — для временного состояния
3. Добавляй условия — для обработки ошибок
4. Тестируй тесты — запускай после каждого изменения
5. Коммить часто — микро-коммиты лучше больших
